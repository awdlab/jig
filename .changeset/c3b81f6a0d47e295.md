**Date filters no longer shift by a day west of UTC.** `JigFilter` writes a date-only value as `YYYY-MM-DD`, but every place that read it back used `new Date('YYYY-MM-DD')`, which the language parses as UTC midnight. In any zone behind UTC that landed on the previous local day: a reopened filter showed the day before, and `executeFilter` matched the wrong day without any visible sign. A shared `parseFilterRawDate()` now reads a bare `YYYY-MM-DD` as local midnight and backs all three readers — the calendar round-trip in the control, `parseFilterRawValue()` and the internal `asDateMs()`. `dateTime` values carry a time (`…T08:30`) and were already parsed as local time, so they are unchanged. The `date` data type now also compares whole local days rather than exact timestamps, so `isEqual` matches any time on the selected day and the range operators include it; `dateTime` still compares the exact instant.
