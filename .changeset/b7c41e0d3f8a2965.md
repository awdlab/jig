**Calendar month navigation no longer snaps back when the host rebinds an equal date.** `JigCalendar` derived its displayed year and month from the bound `value` through a `linkedSignal`, which discards anything written with `.set()` as soon as its source notifies — and a host binding `[value]="parseRawDate(raw)"` hands over a freshly constructed `Date` on every change detection pass. Angular compares inputs with `Object.is`, so a new object always counted as a change, and the previous/next month buttons were undone on the very next pass: the user clicked and nothing moved. `JigFilter`'s date editor binds exactly that way, so its calendar could not be navigated at all once a date was set. The view month now keys on the value's actual year and month rather than on object identity, so an equal `Date` leaves the user's navigation alone while a genuinely different month still moves the view. Hosts that bind a stable signal were never affected.
