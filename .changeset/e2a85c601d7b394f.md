**Attribute filter keys are checked against the item type instead of being plain strings.** `JigFilterAttribute` took its `key` as `string`, so a typo produced a condition that matched nothing at runtime with no sign anything was wrong. The key is now `Extract<AllKeysOfUnion<TData>, string>`, the same shape `jig-table` already uses for its column keys, and falls back to `string` when the payload type is unknown or the generic is left unspecified. An attribute that is computed rather than read from a property supplies a `selector` and may then use any `key` as its identifier — the type requires the selector in that case, so the escape hatch is explicit. `JigFilterAttribute` gained a second parameter for the payload, because `jig-filter-list-box` holds `JigItem`s whose keys index `item.data`: the selector still receives the item while the key is checked against `JigFilterAttribute<Item, Person>`. The new `JigItemsData` exposes that payload type beside the existing `JigItemsValue`, resolving a group to its children's payload. A condition's `attribute` in the emitted configuration stays a `string`, since it must carry a computed attribute's identifier and survive a round trip through a server.
