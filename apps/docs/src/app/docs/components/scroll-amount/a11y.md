### Roles & Attributes

The directive adds no roles or ARIA attributes. It observes scrolling; it does
not change what the element is.

### Keyboard Interaction

None of its own — but the element it observes must be keyboard-scrollable.

A `div` with `overflow: auto` is **not** reachable by keyboard unless it either
contains a focusable element or carries `tabindex="0"`. Add it whenever the
scroll region can hold non-interactive content, so keyboard users can scroll it
with the arrow keys, Page Up/Down and Home/End
([WCAG 2.1.1 Keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)).

A scroll container that takes focus also needs an accessible name — give it
`role="region"` and `aria-label`, or associate a heading with
`aria-labelledby`.

### Infinite Lists

Appending rows on `endReached` changes the page under the user. Make that
perceivable rather than silent:

- announce the load with a polite live region ("20 more items loaded"), or move
  focus to the first new item when the user asked for more explicitly;
- render a visible loading indicator, and give it accessible text — a bare
  spinner announces nothing;
- expose an explicit "Load more" button as well. Auto-loading on scroll is a
  convenience; a keyboard or screen-reader user who cannot easily reach the
  bottom needs a real control.

Infinite lists also strand anything below them. Do not put a footer, or any
content the user needs, after a list that keeps growing.

### Scroll-linked Effects

If you drive animation from `scrollTop`, honour `prefers-reduced-motion` and
keep the effect decorative — content that only appears at a certain scroll
offset is unreachable for anyone who navigates by keyboard or by heading.

### Zoom and Reflow

Because the geometry is measured live, the numbers stay correct at 200% zoom
and after a reflow. Do not cache them across resizes in your own code —
read the signals.
