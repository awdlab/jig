The table exposes an ARIA grid over native table elements. The `role="grid"`
element is the single tab stop; arrow keys move a virtual "current row" —
`aria-activedescendant` points at it, so screen readers announce it without DOM
focus leaving the grid. Which keys are active depends on whether selection and
row actions are enabled.

## Keyboard

| Key                           | Action                                                                                                                                                                    |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ArrowDown` / `ArrowUp`       | Move the current row. In single-select mode selection follows the current row; in multi-select the highlight moves only (hold `Shift` to extend a range from the anchor). |
| `Home` / `End`                | Move to the first / last row.                                                                                                                                             |
| `PageDown` / `PageUp`         | Move ten rows down / up.                                                                                                                                                  |
| `Space` / `Enter`             | Single-select: select the current row. Multi-select: toggle it. On a group-header row: expand/collapse the group.                                                         |
| `ArrowRight`                  | Move into the current row's inline action bar, then between action buttons.                                                                                               |
| `ArrowLeft`                   | Move to the previous action; past the first, exit the bar back to the row.                                                                                                |
| `Enter`                       | With no selection mode and focus on a row: open the row's context menu.                                                                                                   |
| `ContextMenu` / `Shift`+`F10` | Open the current row's context menu.                                                                                                                                      |
| `Escape`                      | Exit the action bar back to the row.                                                                                                                                      |

Row navigation works without selection or row actions — the current row just
moves and scrolls into view.

The inline action bar is also reachable with `Tab`, which makes its row the
current one; leaving it with `Tab`, `Escape` or `ArrowLeft` hands the arrow keys
back to row navigation. The current row shows its action bar only while the grid
has focus.

Sortable column headers are buttons: `Tab` reaches them, `Enter` / `Space`
cycles ascending → descending → unsorted. Column filter buttons are tab stops
too. Per-row selection checkboxes are not (`Space` on the current row toggles
selection instead), so a long table never floods the tab order; the header
select-all checkbox stays reachable.

Column resizing and reordering are pointer-only.

## ARIA & screen readers

Roles come from the table and its directives: `grid`, `rowgroup`, `row`,
`columnheader`, and `gridcell`. The grid sets `aria-multiselectable` in
multi-select mode, `aria-rowcount` (including the header row; `-1` while a lazy
total is unknown), `aria-colcount`, and `aria-busy` while a lazy load is in
flight. Each row carries `aria-rowindex` (header row = 1) and an `id` for
`aria-activedescendant`; each cell carries `aria-colindex` reflecting its
**visual** position, so a reordered column is announced in the order it is seen.
Rows expose `aria-selected` when a selection mode is active, sortable headers
expose `aria-sort`, and the built-in group-header rows expose `aria-expanded`.
Inline action buttons get `aria-haspopup="menu"` when they have children, and
selection checkboxes get localized labels. A visually-hidden `aria-live="polite"`
region announces sort, filter, pagination, selection and load-error changes
(e.g. "Sorted by name, ascending", "12 results", "Page 2 of 5", "3 of 40
selected").

## Developer responsibilities

- Apply the row/cell directives (`jigTableHeadTr`, `jigTableBodyTr`, `jigTableTh`,
  `jigTableTd`) — the grid roles come from them.
- Name the grid with `[label]` or `[labelledBy]` (an element id). Setting
  `aria-label` on `<jig-table>` does not work — the grid role sits on the inner
  `<table>`.
- A custom `#groupHeader` template receives no roles, `id` or `aria-expanded` —
  supply `role="row"`, `role="gridcell"` and `aria-expanded` yourself, and note
  that keyboard expand/collapse and `aria-activedescendant` need the row `id`
  from `rowElementId(index)`. Only the built-in default group row provides them.
