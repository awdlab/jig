The checkbox renders a real native `<input type="checkbox">` (the visible box is a
decorative `<div>`), so checked state and keyboard behavior come from the browser
while the component wires up labelling and validation ARIA.

## Keyboard

| Key     | Action                                        |
| ------- | --------------------------------------------- |
| `Space` | Toggles the checkbox (native input behavior). |

Both `readonly` and `disabled` block toggling from the keyboard: the native input
turns a `Space` press into a `click`, which the control's guard cancels.

## ARIA & screen readers

ARIA is applied to the native input: `aria-label` from `label`, `aria-labelledby`
from `labelledBy`, `aria-invalid="true"` when `invalid`, and `aria-readonly` when
`readonly`. Checked and indeterminate state are set as DOM properties
(`checked`, `indeterminate`), so the input reports its own state. The input stays
focusable while visually hidden; the theme shows focus via `:focus-visible`.

## Developer responsibilities

- Provide an accessible name through `label` (→ `aria-label`) or `labelledBy`
  (→ `aria-labelledby`) — both default to `null`, so the checkbox is otherwise
  unnamed. (`inputId` is generated, so an external `<label for>` also works.)
