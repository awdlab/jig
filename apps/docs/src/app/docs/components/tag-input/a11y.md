### Roles

The text field is a `role="combobox"` with `aria-autocomplete="list"`, `aria-haspopup="listbox"`,
and — while suggestions are shown — `aria-expanded`, `aria-controls` pointing at
`{inputId}_listbox`, and `aria-activedescendant` following the highlighted suggestion.

The tags are a `role="list"` of `role="listitem"`, each with a remove button labelled from the
`tagInput.remove` translation (for example "Remove design").

`aria-invalid` and `aria-required` are reflected from the control's state, and a wrapping
[`jig-input-field`](/components/input-field) picks up `requiredState()` for its asterisk with no
extra wiring.

### Labelling

`jig-input-field` only assigns its `inputId` automatically when the projected control _is_ an
`<input>`, which a composite control never is. Give the field and the tag input the same
`inputId` so the field's `<label for>` reaches the text field:

```html
<jig-input-field [label]="'Labels'" inputId="labels">
  <jig-tag-input inputId="labels" />
</jig-input-field>
```

Without a wrapping field, set `label` or `labelledBy` on the control instead.

### Keyboard

| Key                                             | Behaviour                                                    |
| ----------------------------------------------- | ------------------------------------------------------------ |
| `Enter`                                         | commits the highlighted suggestion, or the typed text        |
| a `delimiters` character                        | commits the typed text; the character never enters the value |
| `Backspace` in an empty field                   | removes the last tag                                         |
| `ArrowLeft` with the caret at the start         | moves focus into the tag row, at the last tag                |
| `ArrowLeft` / `ArrowRight` in the row           | moves between tags, wrapping at the ends                     |
| `Home` / `End` in the row                       | jumps to the first / last tag                                |
| `Delete` / `Backspace` in the row               | removes the focused tag, keeping focus in the row            |
| `Escape` in the row                             | returns focus to the text field                              |
| `ArrowDown` / `ArrowUp` / `PageUp` / `PageDown` | moves the suggestion highlight                               |
| `Escape` with suggestions open                  | dismisses the list, keeping the typed text                   |

The tag row is a single tab stop (the roving-tabindex pattern), so `Tab` leaves the whole control
rather than walking every tag.

### Announcements

A visually hidden `role="status" aria-live="polite"` region reports every change a sighted user
sees as a chip appearing or vanishing:

- a tag added or removed
- a refused tag, with the reason — duplicate, too short, or the limit reached

It is deliberately **not** wired through `aria-describedby`: a live region is announced on change
without association, and hardcoding `aria-describedby` would clobber an app pointing it at a
[`jig-hint`](/components/hint).

### Suggestion visibility

The list follows focus rather than clicks: it is shown while the text field has focus and hidden
when focus leaves. `Escape` dismisses it without giving up focus, and it stays dismissed until
focus leaves and returns — so a user who closed it is not fighting it back open on every
keystroke.

The popover is `manual`, not auto-dismissing, precisely so the click that focuses the field cannot
also light-dismiss the list it just opened.

### Pointer

Pressing a suggestion does not move focus out of the text field, so the half-typed text is never
committed as a tag by the resulting blur.
