Toolbar renders `role="toolbar"` with `aria-orientation`, and gives everything
inside it a single tab stop via a roving tabindex.

## Keyboard

| Key                      | Action                                                |
| ------------------------ | ----------------------------------------------------- |
| `ArrowRight`/`ArrowLeft` | Move focus between controls (horizontal orientation). |
| `ArrowDown`/`ArrowUp`    | Move focus between controls (vertical orientation).   |
| `Home` / `End`           | Focus the first / last control.                       |
| `Enter` / `Space`        | Activate the focused control (native).                |
| `Escape`                 | Close an open overflow popover.                       |

Focus moves across placement boundaries — the three placements are layout, not
separate focus scopes. Disabled controls are skipped and movement stops at the
ends.

Inside an overflow popover, controls use the native tab order rather than a
roving tabindex.

## ARIA & screen readers

Collapsed items stay in the DOM so the toolbar can keep measuring them, but their
in-bar copy is `inert` and `aria-hidden="true"`. Only the copy rendered inside the
popover is exposed, so an item is never announced twice and never becomes a
phantom tab stop.

The `…` trigger is a real button with an `aria-label` (translated via
`toolbar.overflow`) and `aria-expanded`. While no items are collapsed it is
`aria-hidden` and non-interactive.

## Developer responsibilities

- Give icon-only controls inside the toolbar an accessible name.
- Provide a bounded height when using `orientation="vertical"` with
  `overflow="popover"` — otherwise nothing collapses and the `…` never appears.
- Keep item state in the parent component. A collapsible item template renders in
  both the bar and the popover, so internal state would diverge between the two.
