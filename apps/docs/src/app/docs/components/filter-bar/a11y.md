Filter Bar is composed from other controls (input field, button, badge, chip,
filter builder). Most of its accessibility comes from those; the bar itself adds
the wiring between them.

## Keyboard

The search field, the filter trigger and each chip's remove button are in the
natural tab order. The trigger opens the filter builder, whose own keyboard
behaviour is documented on its page.

## Roles and names

- The search input carries an `aria-label` from `filterBar.search`.
- The filter trigger carries an `aria-label` from `filterBar.openFilter`, with
  the active condition count appended — the badge itself is decorative text that
  would otherwise compete with the button's name.
- The chips sit in a `role="group"` named by `filterBar.activeFilters`.
- A chip's remove button is announced as "Remove" and does not repeat the
  condition, because `jig-chip` has no label input yet.

## Disabled and readonly

`disabled` and `readonly` reach the search field, its clear button, the filter
trigger and the chips' remove buttons. They do **not** reach whatever you render
below the bar — pass the same state to it yourself.
