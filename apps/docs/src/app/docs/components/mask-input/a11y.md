Mask input is a segmented editor: a visually-hidden proxy `<input>` is the single
tab stop, and each editable section is a `role="spinbutton"` reached by
active-descendant navigation. It includes a polite live region for step
announcements.

## Keyboard

| Key                                         | Action                                                       |
| ------------------------------------------- | ------------------------------------------------------------ |
| `ArrowUp` / `ArrowDown`                     | Step the active section up/down (announced politely).        |
| `ArrowLeft` / `ArrowRight` / `Home` / `End` | Move between sections.                                       |
| `Backspace` / `Delete`                      | Clear the active section (moves to the previous when empty). |

## ARIA & screen readers

The proxy input carries `aria-roledescription`, `aria-label`/`aria-labelledby`,
`aria-required` (from the `required` input or a bound form control's required
validator), and owns the active-descendant focus over the sections. Each section is a
`role="spinbutton"` with an `aria-label` (the field name), `aria-valuenow`/`min`/
`max`, `aria-valuetext`, and `aria-describedby` pointing at an sr-only
range/options description. Separators are `aria-hidden`. An `aria-live="polite"`
region announces `"{field}: {value}"` as you step a section. `aria-invalid` and
`aria-readonly` mirror the control's state; while readonly, active-descendant
navigation is suspended, so the proxy input is the whole widget and the sections
are inert `aria-readonly` spinbuttons.

## Developer responsibilities

- Provide a `mask` — with none, nothing renders.
- Give the field an accessible name via `label` or `labelledBy`.
- Ensure the mask-input i18n strings (role description, segment range, option
  separator) are translated — the section descriptions depend on them.
