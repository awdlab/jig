Filter Builder is a condition builder composed from other controls (select,
input, calendar, buttons, popover). Most of its accessibility comes from those
sub-controls; the filter itself adds only a little wiring.

## Keyboard

| Key               | Action                                                           |
| ----------------- | ---------------------------------------------------------------- |
| `Enter`           | Toggle the popover (in the non-inline `input`/`headless` modes). |
| `Enter` / `Space` | Toggle the match-mode divider (`role="button"`).                 |

Navigation within the property and operator selects, value editor, calendar,
and buttons is handled by those controls.

## ARIA & screen readers

Each row's property and operator selects are named by the localized
`filterBuilder.property` and `filter.operator` labels. The value input and
each remove-condition button carry localized `aria-label`s (the remove button
appends the row number), and the match-mode divider is `role="button"` with
`aria-disabled`. There is **no** `aria-expanded`/`aria-haspopup`/`aria-controls`
wiring between the trigger and the popover, and no live region for result
changes.

## Developer responsibilities

- Provide `data` and `properties` (and an `anchor` in `headless` mode).
- Give each property a human-readable `label` — it is the only name the
  property select offers.
- Provide an accessible name — `label` is only rendered in `input` mode; give
  inline/headless usages their own context.
- Supply the property filter and filter i18n translations.
