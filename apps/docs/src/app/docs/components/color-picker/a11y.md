## Structure

In popover mode the control renders a `<button type="button">` trigger with
`aria-haspopup="true"` and `aria-expanded` reflecting whether the panel is
open. In `inline` mode the panel renders directly, without a trigger.

Inside the panel, the saturation/value area, hue track, and alpha track are
pointer-drag surfaces (click or drag to set a value). The format toggle and
the color text field are a native `<button>` and `<input>`, and swatches are
native `<button>` elements — all are reachable via `Tab` and operable with
`Enter`/`Space` or by typing.

## Keyboard

- The format toggle and swatch buttons are focusable and activate with
  `Enter`/`Space`, like any native button.
- The text field accepts typed hex/`rgb()`/`hsl()` values directly.
- The saturation/value area, hue track, and alpha track have no keyboard
  equivalent yet — adjusting them requires a pointer. Keyboard users should
  rely on the text field (and swatches, if provided) to set a color.

## Developer responsibilities

- This control does not currently reflect `label`/`labelledBy` onto the
  trigger button or panel — wrap it in a `<label>` or add your own
  `aria-label`/`aria-labelledby` to the host so the control (and its trigger,
  which otherwise exposes only a color swatch) has an accessible name.
- If your users need full keyboard control over hue/saturation/alpha, pair
  the picker with the text field as the primary input method — don't rely on
  the drag surfaces alone.
- When using swatches, pick colors with enough contrast between each other so
  they remain distinguishable to low-vision users, since they're
  communicated purely by color.
