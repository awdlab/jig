The skeleton renders with `aria-hidden="true"` and no `role`. It is decorative:
screen readers skip it entirely, and it is not focusable or interactive.

That means the skeleton alone tells assistive tech nothing. Announcing the
loading state is the surrounding region's job.

## Keyboard

| Key | Action                                   |
| --- | ---------------------------------------- |
| —   | No keyboard interaction; presentational. |

## ARIA & screen readers

Put the busy state on the container that will hold the real content:

```html
<section role="status" aria-live="polite" aria-busy="true" aria-label="Loading release notes">
  <jig-skeleton width="55%" height="1.5rem" />
  <jig-skeleton />
</section>
```

- **`aria-busy="true"`** is the correct attribute for "this region is being
  updated". Remove it (or bind it to your loading signal) once the content is
  there — a region left permanently busy suppresses updates.
- **`aria-live="polite"`** makes the swap announce when it completes. Without a
  live region the content appears silently.
- **`aria-label`** (or a visually hidden heading) gives the region a name while
  it is empty, so the announcement says what loaded.

Do not use `aria-hidden` on the container — that would hide the real content too.

## Reduced motion

Under `prefers-reduced-motion: reduce` the shimmer (a gradient sweep or an
opacity pulse, depending on the theme) stops and the placeholder renders as a
flat block. It is decorative and `aria-hidden`, so nothing is lost.

## Developer responsibilities

- Set `aria-busy` on the region while loading and clear it afterwards.
- Give the loading region an accessible name; an unnamed busy region announces
  nothing useful.
- Keep the skeleton's proportions close to the real content so the swap doesn't
  shift focus or scroll position.
- Prefer a skeleton over a spinner only when you know the shape of what's
  coming; otherwise `<jig-spinner>` with `role="status"` carries the state
  itself.
