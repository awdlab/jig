`ngnButton` is an attribute directive on a native `<button>` or `<a>`, so keyboard
handling, focus, and disabled behavior all come from the browser — the directive
only styles the element and never overrides its semantics.

## Keyboard

| Key     | Action                                                    |
| ------- | --------------------------------------------------------- |
| `Enter` | Activates the element (native `<button>` and `<a>`).      |
| `Space` | Activates a `<button>` (native; not applicable to `<a>`). |

The directive adds no key handlers of its own.

## ARIA & screen readers

The directive sets no `role` or `aria-*` attributes — a `<button>` is announced
as a button and an `<a>` as a link. An icon-only `<awd-action-button>` gets its
accessible name from `NgnTooltip` (`ngnTooltipAutoAriaMode="label"` with the
plain `config.label` as content), and the directive passes the `disabled` flag
through to the native button. A configured `shortcut` renders its glyphs inline
as a hidden `<awd-kbd aria-hidden="true">`, so they never join the accessible
name or the tooltip text.

## Developer responsibilities

- Give every button an accessible name: visible text content, or an `aria-label`
  when the button is icon-only. `<awd-action-button>` icon buttons take this from
  `config.label` via their tooltip.
- A native `<a>` has no `disabled` attribute — render it conditionally or
  intercept navigation instead of relying on a disabled state.
