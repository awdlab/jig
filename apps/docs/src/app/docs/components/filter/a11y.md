Filter is a condition builder composed from other controls (select, input,
calendar, buttons, popover). Most of its accessibility comes from those
sub-controls; the filter itself adds only a little wiring.

## Keyboard

| Key               | Action                                                           |
| ----------------- | ---------------------------------------------------------------- |
| `Enter`           | Toggle the popover (in the non-inline `input`/`headless` modes). |
| `Enter` / `Space` | Toggle the match-mode divider (`role="button"`).                 |

Navigation within the operator select, value editor, calendar, and buttons is
handled by those controls.

## ARIA & screen readers

The value input and each remove-condition button carry localized `aria-label`s,
and the match-mode divider is `role="button"` with `aria-disabled`. There is
**no** `aria-expanded`/`aria-haspopup`/`aria-controls` wiring between the trigger
and the popover, and no live region for result changes.

## Developer responsibilities

- Provide `data` and `dataType` (and an `anchor` in `headless` mode).
- Provide an accessible name — `label` is only rendered in `input` mode; give
  inline/headless usages their own context.
- Supply the filter i18n translations.
