Inplace toggles between a display trigger and a content view. The display view is
a native `<button>`, so opening is native.

## Keyboard

| Key               | Action                                                          |
| ----------------- | --------------------------------------------------------------- |
| `Enter` / `Space` | Open the content view from the display trigger (native button). |

There is no built-in `Escape`-to-close — the content template gets a `close`
callback to wire its own dismissal.

## ARIA & screen readers

The display view is a native `<button>` and the content is a plain `<div>`. The
toggle exposes **no** `aria-expanded`/`aria-controls` relationship between the two.

## Developer responsibilities

- Provide `#display` and `#content` templates; the content template receives a
  `close` callback.
- If the open/closed relationship should be announced, add `aria-expanded`/
  `aria-controls` yourself — the control does not.

## Focus

Focus follows the display↔content swap so it is never dropped when the outgoing
view unmounts. On **open**, focus moves into the content region; on **close**, it
returns to the display trigger. Both act only when focus would otherwise fall to
the document body — so a content control that autofocuses itself (e.g.
edit-inplace's input) keeps focus, and focus that has moved elsewhere is left
alone.
