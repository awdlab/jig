### Roles & Attributes

The directive adds no roles or ARIA attributes. It only calls `focus()` on its
host, so the host must be focusable on its own — a form control, a button, a
link, or an element with `tabindex`.

### Keyboard Interaction

None. The directive does not handle keys; it only moves the initial focus.

### Use it sparingly

Moving focus without the user asking is disorienting for screen-reader and
screen-magnifier users, and it scrolls the viewport to the focused element.
[WCAG 3.2.1 On Focus](https://www.w3.org/WAI/WCAG22/Understanding/on-focus.html)
also forbids a focus change from causing a change of context on its own.

Autofocus is appropriate when:

- the user's action created the element (opening a search field, entering an
  edit mode, adding a row), and
- the focused element is the obvious next step, and
- it is at or near the start of the newly revealed content.

It is inappropriate on ordinary page load: it robs the user of the document
start, skips past everything above the field, and on small screens can pop the
on-screen keyboard immediately.

### Announcement

Focusing an element makes assistive technology announce it, so its accessible
name must already be correct at that moment. Wire the label up front — via
`<ngn-input-field [label]>`, `aria-label`, or `aria-labelledby` — rather than
setting it after the focus lands.
