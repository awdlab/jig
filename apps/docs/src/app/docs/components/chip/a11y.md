A chip is display-only by default. It becomes interactive when `actionable` (its
content is a native `<button>`) and/or `closable` (a native remove `<button>`).

## Keyboard

| Key               | Action                                                                      |
| ----------------- | --------------------------------------------------------------------------- |
| `Enter` / `Space` | Activate an actionable chip, or operate the remove button (native buttons). |

A plain (non-actionable, non-closable) chip has no keyboard interaction.

## ARIA & screen readers

Interactive parts are real `<button>` elements. The remove button has a localized
`aria-label` (from the `chip_close` translation). The chip host sets no `role`.

## Developer responsibilities

- If the chip's content is non-textual, give it an accessible name — the component
  does not.
- The chip host has no `role`. When a chip is a semantic item in a larger widget
  (an option in a listbox, a removable token in a group), give it the role that
  context requires — the component sets none.
- The remove button is labelled automatically; change the `chip_close` translation
  to adjust its wording.
