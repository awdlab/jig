### Roles & Attributes

The directive adds no roles or ARIA attributes. The resize grip is the
browser's native one, drawn by the CSS `resize` property — it is not a DOM
element, so it cannot carry a label or be reached by assistive technology.

### Keyboard Interaction

**None.** The native CSS resize grip is pointer-only in every current browser.

Treat resizing as a convenience, never as a step the user must complete. If the
content must be readable at a larger size, it has to reflow or scroll on its
own — see [WCAG 1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
— rather than requiring a drag.

Where the size genuinely matters, offer a non-drag alternative: preset size
buttons, a maximize toggle, or a persisted size the user sets once. This is
also what [WCAG 2.5.7 Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)
asks for.

### Content Behaviour

Because the host must have a non-`visible` `overflow`, shrinking it clips or
scrolls its content. Set `minWidth`/`minHeight` generously enough that the
control's essential content — labels, actions, error messages — is not cut off
at the smallest allowed size, especially at 200% zoom.

### Reduced Motion

Nothing here animates, so there is no `prefers-reduced-motion` concern. Avoid
adding transitions on `width`/`height` yourself: they lag the pointer and make
the grip feel broken.
