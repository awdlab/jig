Dialog is built on the native `<dialog>` element. In modal mode it opens with
`showModal()`, so the browser provides focus containment and returns focus to the
trigger on close; non-modal mode uses the native Popover API.

## Keyboard

| Key                   | Action                                                                                                                                                |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Escape`              | Modal: native `cancel` closes it (subject to `closeBy`). Non-modal: closes only when `closeBy` is `escape` and focus is on the dialog element itself. |
| `Tab` / `Shift`+`Tab` | Native focus containment within the modal (browser-provided).                                                                                         |

For a non-modal dialog, `Escape` cannot safely close while focus is inside a
child element, so it is ignored in that case.

## ARIA & screen readers

Modal semantics (dialog role, focus trapping) come implicitly from the native
`showModal()` — no `role`/`aria-modal` is authored. `aria-labelledby` always
points at the header id; the default `<h2>` receives that id only when a `title`
is set. The close button has a localized `aria-label` and is removed from the tab
order (`tabindex="-1"`).

## Developer responsibilities

- Provide a `title`, or a custom header element carrying the header id. Without
  one, `aria-labelledby` references a missing element and the dialog is
  effectively unlabeled.
- `autofocus` defaults to the modal flag; set an explicit autofocus target for a
  sensible initial focus.
